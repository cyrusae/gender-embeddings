Scripts: `check.py`, `check2.py` (run: `uv run --no-project --with numpy,scikit-learn python check.py`), `show.py` (prints notebook cells), `nb_dump.txt`/`paper.txt` (dumps). Data: first 50,000 lines of `wiki.multi.es.vec`. Only Spanish was computed; French not run.

## What the code computes (relied on for all claims)
- MWEAT is cell 222 lines 1-34 (also cell 217). Lines 15-19 use RAW DOT PRODUCTS `embeddings[...].dot(...)`, not cosines (the paper, §4.2 and §2, says cosine). MUSE vectors are not guaranteed unit norm (the ES sample has median norm 1.0 but they are not exactly unit). Return value (line 33-34): `[T_X - T_Y, abs(abs(T_X) - abs(T_Y))]`, with T_X = sum over male forms of (mean_M . w - mean_F . w) = sum_x x.a, a = mean(male attrs) - mean(female attrs); T_Y same for female forms. Table 1 "MWEAT-Diff" = index 1 (`modified=1` default in cell 230 line 9).
- Shift Ori on occupations (cells 273 and 312): offset_k = -0.5 (f_k.d + m_k.d) (cell 273 lines 4-5); both forms get `+= offset_k * d/(d.d)` (cell 312 lines 3-7). Both forms move by the same amount along d.
- Eq. (2) / `drop` appears only in cells 247 and 248 (lines 3,7 and 7,11), on the career/family WEAT target words, not on inanimate nouns generally.

## Claim 1 (identity): PARTLY (true as an exact identity under stated conditions; the wording overstates)
Derivation (checkable by hand). Let pairs k = 1..n with masculine m_k, feminine f_k. Attribute vector a = mean(M) - mean(F) is fixed (occupation words are the only ones moved). Let d be any fixed vector, delta_k = -1/2 (m_k.d + f_k.d), and shifted words w' = w + delta_k d/(d.d) (same delta_k for m_k and f_k).
1. Score of a word is linear in the word: s(w) = w.a. So T'_X = sum_k m'_k.a = sum_k m_k.a + c, T'_Y = sum_k f'_k.a = sum_k f_k.a + c, with the SAME c = (d.a)/(d.d) * sum_k delta_k.
2. Add: T'_X + T'_Y = sum_all w.a + 2c = sum_all w.a - (d.a)/(d.d) * sum_all w.d = sum_all w.(a - d (d.a)/(d.d)) = sum_all w.a_perp. Exact, holds for any d (not only unit), any pairs, and is independent of how the words are split into X and Y.
3. Subtract: T'_X - T'_Y = T_X - T_Y (the common shift cancels).
4. Statistic S = | |T'_X| - |T'_Y| |. If T'_X and T'_Y have opposite signs, | |u|-|v| | = |u+v|, so S = |sum_all w.a_perp| (the claim). If they have the same sign, S = |T'_X - T'_Y| = |T_X - T_Y| (the ORIGINAL signed difference), also fixed by the original embeddings.
So the claim holds with these conditions: (i) dot-product MWEAT, as in the code (with cosines, w' renormalises and linearity is lost: step 1 fails; numerically cosine version gave 0.322 vs 0.1155 dot); (ii) attribute words not moved (if they are moved, as in cells 279/297/306, the identity still holds but with the post-shift a and a_perp; I verified numerically, 0.1155 both ways, the shift of attributes changes a.d only slightly); (iii) the same offset for both forms, offsets computed from the unshifted vectors, and every word in exactly one pair (no duplicates in the 59 pairs; a word in two pairs would be shifted twice and break (f'+m').d = 0); (iv) the OPPOSITE-SIGN condition. Without (iv) it is not "|sum|" but the original signed difference. (iv) held in my reconstruction (T'_X=+4.88, T'_Y=-4.99); in the paper's setting it cannot be checked.
Overstatements: "reflects no change in the masculine/feminine asymmetry" is true only for this statistic: a_perp still contains whatever bias is orthogonal to d_s, and sum w.a_perp is itself a (signed, pooled) association of ALL occupation words with the attribute axis, not nothing; it is just not an asymmetry measure between forms. Also the MWEAT is not "fixed" by the original embeddings alone: it depends on d_s (an estimate) and on which words are attributes.
Numerics (our reconstruction on original MUSE ES, d_s from notebook-style PCA + LinearSVC, 59 pairs incl. doctora added in cell 211): Original Diff 3.8155 (paper 3.6918, differs; cannot match because the repo's noun files/unknown state differ). After shift: 0.115519; |sum w.a_perp| = 0.115519; T'_X+T'_Y = -0.115519; max |(m'+f').d_s| = 1.2e-16. Identity exact to machine precision. Paper's 0.3090 not reproduced (needs debiased-aligned vectors / their exact d_s, not available).
Gender direction cos 0.389: closest match is the notebook's own PCA (cell 36, with its center = a + b/2 precedence bug) on the 10 JSON pairs vs LinearSVC on the first 3000 noun pairs: +0.3885 (cell 77 prints 0.38851). With 12 pairs 0.3925, corrected centre 0.374, LDA 0.377. So the SVC + notebook PCA (10 pairs) estimator reproduces 0.389; the PCA bug (cell 36 line 6) is not the paper's stated method but matches the number.

## Claim 2 (permutation p-values meaningless): PARTLY / mostly CONFIRMED for the dot-product statistic
Relevant code: cell 230 lines 9-33: line 27 `c = random.sample(all_targets, len(tw1))`, line 28 `not_c = filterfalse(...)`, line 30 `observed_over.append(stat > test_stat)` (strict >). A random split of the pooled 118 words keeps T_X+T_Y = sum_all w.a (cell-level invariant), so after Shift Ori any split with opposite signs gives S = |C| exactly (same as observed when observed is opposite-signed). In my reconstruction 90.4% of 20,000 permutations are ties with the observed statistic (opposite-sign share 0.904); the remaining 9.6% are smaller. Only strict ">" counts, so mathematically p = 0; but ties are tied only in exact arithmetic: with floating point, different summation orders give differences around 1e-16, so "stat > test_stat" is decided by rounding. Using notebook-style summation I got "strictly greater" in 90.2% of draws (p ~ 0.90), a number set by rounding error, not the data. The notebook printed 0.269 for cell 305 (seed 520, 1000 draws), the paper reports 0.733 for Hybrid Ori; they differ from each other and from mine, consistent with rounding-dependent values. Caveats: this is on my reconstruction of Shift Ori (not the authors' embeddings); the tie share depends on |C| relative to word score spread. "Not meaningful" is right for those columns; "a large share reproduce exactly" confirmed here (about 90%), exact share for the authors' embedding unknown. On Original embeddings the permutations give 0% ties (p-value 0 is genuine). The same logic does not apply to Shift EN / De-Align / Hybrid EN (anchors differ), which are not covered.
